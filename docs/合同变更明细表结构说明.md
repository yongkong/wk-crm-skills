# 合同变更明细表（wk_zj_jt_contract_change_detail）表结构说明

## 基本信息

| 属性 | 值 |
|------|-----|
| 表名 | `wk_zj_jt_contract_change_detail` |
| 注释 | 合同变更内容明细表 |
| 引擎 | InnoDB |
| 字符集 | utf8mb4 / utf8mb4_0900_ai_ci |
| 行格式 | DYNAMIC |
| 所属数据库 | zj_crm |
| SQL文件 | `zhongjicheliang/DB/wk_zj_jt_contract_change_detail.sql` |

## 字段定义

| 字段名 | 类型 | 可空 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `id` | bigint | NOT NULL | - | 主键ID |
| `change_id` | bigint | YES | NULL | 变更ID（关联合同变更主表） |
| `seq_no` | int | YES | NULL | 序号 |
| `change_detail_code` | varchar(50) | YES | NULL | 变更明细代码 |
| `change_detail_item` | varchar(255) | YES | NULL | 变更明细项 |
| `change_detail_desc` | text | YES | NULL | 变更明细描述 |
| `unit_config_price_diff` | decimal(18,2) | YES | NULL | 单台配置差价（元） |
| `config_price_diff_total` | decimal(18,2) | YES | NULL | 配置差价合计（元） |
| `unit_change_handling_fee` | decimal(18,2) | YES | NULL | 单台变更手续费（元） |
| `change_handling_fee_total` | decimal(18,2) | YES | NULL | 手续费合计（元） |
| `file_batch_id` | varchar(50) | YES | NULL | 附件批次ID（H3增加喷涂方案/H4更改喷涂方案使用） |
| `create_user_id` | bigint | YES | NULL | 创建人ID |
| `create_time` | datetime | YES | NULL | 创建时间 |
| `company_id` | bigint | YES | NULL | 公司ID（多租户隔离） |
| `deleted` | tinyint(1) | NOT NULL | 0 | 逻辑删除标记（0=未删除，1=已删除） |

## 索引

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `PRIMARY` | `id` | 主键 | 主键索引 |
| `idx_change_id` | `change_id` | 普通索引 | 按变更ID查询明细 |
| `idx_company_id` | `company_id` | 普通索引 | 按公司ID隔离查询 |

## 表关系

```
wk_crm_zj_jt_contract_change（合同变更主表）
  └── wk_zj_jt_contract_change_data（变更扩展数据）
  └── wk_zj_jt_contract_change_detail（变更内容明细）  ← 当前表
  └── wk_zj_jt_contract_change_vehicle_detail（变更车辆明细）
  └── wk_crm_jt_contract_change_content_detail（变更内容详情-旧）
```

- 通过 `change_id` 字段关联合同变更主表 `wk_crm_zj_jt_contract_change`
- 一个变更主记录可对应多条明细记录（一对多关系）

## 业务说明

1. **用途**：存储合同变更的明细项信息，每条记录代表一个变更明细项
2. **金额字段**：包含单台配置差价、配置差价合计、单台手续费、手续费合计四个金额字段，精度为 decimal(18,2)
3. **附件支持**：通过 `file_batch_id` 字段支持附件上传，主要用于 H3（增加喷涂方案）和 H4（更改喷涂方案）场景
4. **逻辑删除**：采用 `deleted` 字段进行软删除，不做物理删除
5. **多租户**：通过 `company_id` 实现数据隔离
