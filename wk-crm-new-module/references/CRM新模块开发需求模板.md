## 四、业务逻辑（按需填写）

### 4.1 状态流转

> 描述业务状态及流转规则：

| 规则类型 | 规则描述 | 触发时机 | 说明 |
|---------|---------|---------|------|
| 状态流转 | 草稿→审核中→已通过/已驳回；已驳回可重编辑；已通过不可编辑 | 保存/提交/审批回调 | checkStatus 状态机定义 |
| 自动填充 | 选择合同后自动填充客户名称、业务经理、合同金额 | 表单 change 事件 | 减少手工输入 |
| 计算规则 | 配置差价合计 = 单台差价 x 台数 | 表单 change 事件 | 前端实时计算 |
| 校验规则 | 审批中/已通过的单据不可重复提交；已作废不可编辑 | 提交前校验 | 防止重复操作 |
| ERP 集成 | 审批通过后同步 ERP 系统；撤回时逆向通知 | 审批回调 | L3+ 才需要 |
| 编号规则 | 格式：BG-{yyyyMMdd}-{4位序号}，每日重置 | 新建保存时 | serial_number 类型字段 |

### 4.2 ERP 集成（L3+ 填写）

| 逆向作废 | 撤回时 | /api/erp/xxx/cancel | 通知 ERP 作废 |

## 六、菜单与权限

### 6.1 菜单结构

```
CRM 根菜单（已有 parent_id=1）
  └── {模块中文名}（目录菜单）
      ├── 查看 (index)         ← menu_type=2（页面路由）
      ├── 新建 (save)          ← menu_type=3
      ├── 编辑 (update)        ← menu_type=3
      ├── 删除 (delete)        ← menu_type=3
      ├── 转移 (transfer)      ← menu_type=3
      └── 查看详情 (read)      ← menu_type=3
```

> 标准 6 按钮：index / save / update / delete / transfer / read，menu_id 从基址+1 到基址+6。
> 如需额外权限按钮（如"作废"、"撤回"），从基址+7 起追加：

| 按钮名 | realm | 说明 |
|--------|-------|------|
| 作废 | cancel | 作废后不可恢复 |
| 撤回 | withdraw | 审批中可撤回 |
